## Family notes

ADMIN CONSOLE — CROSS-CUTTING FACTS

1. SEPARATE SHELL. /admin does NOT use the (platform) AppShell. `app/admin/layout.tsx` is a 'use client' layout that renders its own fixed left sidebar at **w-64 = 256px** (not the 240/68px platform sidebar), **no right icon rail**, **no desktop topbar**, **no command palette**, **no ComplianceFooter/DisclaimerFooter**, and **no max-width cap on main** (only `/admin/model-performance` and `app/admin/loading.tsx` self-cap at `max-w-7xl` = 1280px). Main is `lg:pl-64` with inner `p-6 lg:p-8` (24px → 32px).

2. ADMIN IDENTITY COLOUR IS WARNING, NOT THE BRAND BLUE. The whole console is keyed on `--color-warning` = **#F0A94F on dark / #9A4D00 on light** — the Shield logo tile, the "ADMIN" eyebrow, the active nav pill + its 4×24px left rail bar, the user avatar circle, every "Refresh" button on /admin and /admin/ml, the active period-selector chip on /admin/payments and /admin/signals (`bg-warning text-black`), the Search submit on /admin/users, and input focus rings (`focus:border-warning/60`). Brand blue #406AE4 appears only as `hover:border-primary` on cards, tinted "primary" chips, the LLM-cost active window chip, the Training "Run all" button, and the kill-switch "Clear" button.

3. THE CARD PRIMITIVE IS `.glass-card`, AND IT HAS **NO BORDER-RADIUS**. globals.css defines `.lg-surface, .glass-surface, .glass-card { background: var(--color-wrap); border: 1px solid var(--color-line); box-shadow: var(--elev-1); }` — no radius rule anywhere. So every `glass-card` in the admin console renders with **square 0px corners**, L1 fill (#151517 dark / #FFFFFF light), a 1px hairline (#29292D / #DDE5ED) and elev-1. Almost all of them add `hover:border-primary transition-colors` so the hairline turns #406AE4 on hover. Panels that DO have radius use explicit classes: `rounded-lg` (16px) for the ML regime banner and the /admin/system status banner, `rounded-md` (12px) for the Training cards, kill-switch panel, error/alert strips and the user-detail cards, `rounded-sm` (8px) for buttons/inputs/list rows, `rounded-xs` (6px) for micro chips and audit/scheduler/LLM controls, `rounded-full` for status pills.

4. RADIUS SCALE (tailwind.config.ts): mark 2px · xs 6px · sm 8px · md 12px · lg 16px · full 9999px. SPACING scale 0/4/8/12/16/20/24/28/32/40/48/64/80/96/128px.

5. TYPOGRAPHY AS BUILT IS LEGACY, NOT THE 7-ROLE SCALE. Admin pages use `text-3xl` (30/36) for h1 on /admin, /admin/users, /admin/payments, /admin/signals, /admin/system; `text-2xl` (24/32) on /admin/training, /admin/users/[id], /admin/model-performance; `text-lg` (18/28) for every card h2/h3; `text-sm` (14/20) for labels; `text-xs` (12/16) for meta; and a lot of arbitrary `text-[10px]` / `text-[11px]` / `text-[12px]` / `text-[13px]` inside the PR-47/PR-49/PR-129 panels (below the stated 11px floor in places). Numerics use `font-mono num-display` (Geist Mono, tabular-nums, -0.02em) or the `.numeric` class (-0.01em). Fonts are **Geist Sans + Geist Mono** loaded on `<html>` by the root layout; body is `font-sans bg-main antialiased noise-overlay`.

6. THEME. Dark is `:root` default, light is `html.light`. Everything is token-driven so both themes work, BUT the admin pages hardcode `text-white` and `text-black` in ~200 places (e.g. `text-white` headings, `text-black` on warning fills), so in light mode those literals do not flip — a redesign must replace them with `text-d-text-primary` / `text-primary-foreground`.

7. SHARED SEMANTIC MAP used by every page: up #10B981/#0A6B50 · down #F5808C/#B81C22 · warning #F0A94F/#9A4D00 · accent fill #406AE4 (hover #3055C2) · accent/AI ink #8FB0FF dark / #3459C9 light · cyan #5290F4/#2563EB · ink #F7F7F8/#D3D3D7/#96969E dark, #1D1D1D/#4D585F/#5F6B75 light · surfaces L0 #0D0D0E, L1 #151517, L2 #1E1E21, L3 line #29292D, L4 #3B3B40 (light: #EDF1F4 / #FFFFFF / #F4F7F9 / #DDE5ED / #C8D4DE). Tint recipe repeated everywhere: `bg-<tone>/10 border-<tone>/20 text-<tone>`.

8. LOADING IDIOM. Five of the nine pages block the entire route with a centered `.loader-rings` inside `h-96` (384px) — a 48px dual-ring spinner: outer ring 3px transparent with top border #406AE4 spinning 2s linear, inner ring inset 6px with right border #8FB0FF spinning 1.5s reverse. `/admin/users/[id]` instead uses a 48px `animate-spin rounded-full border-t-2 border-b-2 border-down` circle. Only `/admin/model-performance` and `app/admin/loading.tsx` use foundation `Skeleton`. There is no skeleton parity across the console.

9. FOUNDATION USAGE IS THIN. Only `/admin/model-performance` (Badge, Button, EmptyState, Skeleton) and the kill-switch panel (ConfirmDialog) use `components/foundation`. Every other admin surface is hand-rolled markup: raw `<table>`, raw `<select>`, raw `<input type="checkbox">`, raw pills. No DataTable, no Tabs, no Segmented, no Sheet, no Dialog (except ConfirmDialog), no PageHeader, no toast — feedback on /admin/users and /admin/users/[id] is native `prompt()` / `confirm()` / `alert()`, and on /admin/system Manual Operations it is native `confirm()`.

10. NAV vs ROUTES. The sidebar lists **7** items (Dashboard, Users, Payments, Signals, ML Models, Training, System Health). `/admin/model-performance` is **orphaned** — nothing links to it anywhere in the repo; it is direct-URL only. `/admin/users/[id]` is reached from the row kebab menu → "View Details".

11. GATING. The whole group is `admin` auth state. `AdminLayout` calls `GET ${NEXT_PUBLIC_API_URL}/api/admin/verify` with a Supabase bearer token; while `loading || isAdmin === null` it renders a full-viewport loader-rings, and on `is_admin !== true` (or any fetch error) it renders a centered Access Denied screen instead of children. No tier gate, no broker gate — admin is binary.

12. LIVE BEHAVIOUR. Only three surfaces poll: `/admin/system` has an opt-in "Auto-refresh (30s)" checkbox (setInterval 30000), `/admin/training` polls every 3000ms while any run has status `running`, and `/admin/model-performance` uses SWR with `revalidateOnFocus:false, dedupingInterval:60_000`. Everything else is fetch-on-mount + manual Refresh. Three pages ( /admin, /admin/signals, /admin/system ) show a decorative "Live" chip — a 6px `bg-up animate-pulse` dot plus the word "Live" — that is NOT tied to any socket.

13. CURRENCY + LOCALE. Rupee is emitted as the escaped `'₹'` literal, values via `toLocaleString()` (browser default locale) on /admin and /admin/payments and `₹` literal on /admin/users/[id]. Payment amounts are divided by 100 (paise → rupees). Timestamps are `toLocaleString()` / `toLocaleDateString()` / `toLocaleTimeString()`, except the PR-47/49 panels which explicitly pass `'en-IN'`. The drift panel footer states "refreshed Sunday 02:00 IST".

14. KNOWN DEAD/INERT UI worth preserving-or-fixing decisions on: `/admin/payments` declares a `search` state and imports `Search`/`TrendingUp`/`AlertCircle` but renders no search field; its Actions column renders a literal em dash "—" for every row with the comment that refunds are Razorpay-dashboard-only. `/admin/users/[id]` renders Suspend/Unsuspend/Ban buttons with **no onClick** — they are visually complete and do nothing; only "Reset Subscription" is wired. `/admin/users` refetches on every keystroke because `search` is in the fetch callback deps (no debounce) in addition to the explicit Search button.

## `/admin/*` — Admin shell

**File** `app/admin/layout.tsx` · **203 LOC** · **Access** admin — hard gate. Requires an authenticated Supabase session AND `GET /api/admin/verify` returning `{ is_admin: true }`. No tier gate, no broker gate. Non-admins get a full-page Access Denied screen instead of children; unauthenticated users fall through to `is_admin=false` because `user?.email` is missing.

**Shell** — This IS the shell. Wrapped only by the root layout (`app/layout.tsx`: `<html>` with Geist Sans/Mono variables, `<body class="font-sans bg-main antialiased noise-overlay">`, a `min-h-screen` div and `<Providers>`). Root layout does not inject any nav.

**Purpose.** The chrome every admin route renders inside. It gates access on a server-verified admin flag, gives the operator a persistent 7-item task list keyed on the amber admin identity colour, and keeps identity + escape hatches (back to the product, sign out) permanently visible at the bottom of the rail.

Sidebar width never changes — it is 256px on a 360px phone too, covering 71% of the screen.
