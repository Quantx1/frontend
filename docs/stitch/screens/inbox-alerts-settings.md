## Family notes

SHELL / LAYOUT SPLIT — this is the single most important structural fact for a redesigner. Only two of the four routes live in the (platform) route group: /inbox (app/(platform)/inbox/page.tsx) and /referrals (app/(platform)/referrals/page.tsx). Those get AppShell from app/(platform)/layout.tsx, which ALSO mounts SystemHaltBanner (dynamic, ssr:false) above and AutopilotStickyStop below, runs the first-login onboarding redirect to /onboarding/broker-connect, the pending_ref referral-attribution fallback, and the Web Push service-worker subscription. /alerts (app/alerts/page.tsx) and /settings (app/settings/page.tsx) sit at the app root and each render <AppShell> themselves on EVERY return path (including their loading and signed-out states) — so they get the same 3-zone chrome but none of the platform-layout side effects. Do not add a shared layout without deduplicating those AppShell calls.

CONTENT WIDTHS DIFFER PER ROUTE inside AppShell's max-w-[1440px] px-4 md:px-6 gutter: /inbox = max-w-4xl (896px), /referrals = max-w-5xl (1024px) with its own px-4 md:px-6 py-8, /settings = max-w-6xl (1152px), /alerts = w-full (uncapped). app/settings/loading.tsx models max-w-3xl (768px), which does not match the page it stands in for.

SHARED COMPONENT — AlertPreferencesGrid (components/settings/AlertPreferencesGrid.tsx) is DUAL-MOUNTED: it is the third section of /alerts and the first child of the Settings → Notifications tab. Both mounts use the same SWR key 'alerts_preferences', so SWR dedupes to one GET; /alerts additionally writes into that shared cache from its bulk Enable-all/Mute-all controls so both surfaces re-render in lockstep. Any redesign must keep it as one component — it is a 5-column table (Event + Push/Telegram/Whatsapp/Email) of 36×20 pill toggles, 18 backend-driven rows × 4 channels = 72 independent optimistic switches, and it self-declares '{N} event types · 4 channels. Auto-syncs new event types as the backend adds them.'

THREE SEPARATE ALERT SYSTEMS, deliberately kept visually distinct and sharing no backend: (a) event×channel routing preferences → /alerts + Settings→Notifications; (b) per-symbol price thresholds → /watchlist (linked out from /alerts, never rebuilt there); (c) per-signal push toggles → /signals/[id]. The /alerts page carries an explicit card explaining (b) is elsewhere. Do not merge them.

TIER GATING — only /alerts is gated: the `alert_studio` feature flag (Pro+, admins bypass) produces a dedicated paywall EmptyState with a Lock icon and an `ai`-variant 'Upgrade to Pro' button, rendered INSTEAD of the studio so no 403 ever reaches the grid. /inbox, /referrals and /settings are open to every authed tier; Settings surfaces tier state through TierPanel (Free ₹0 / Pro ₹999/mo / Elite ₹1,999/mo, hardcoded bullet lists) and an 'Admin' pill.

SURFACE VOCABULARY used across all four screens: cards are `rounded-sm border border-line bg-wrap` (8px) for section panels and `rounded-lg` (16px) for the two Settings containers; nested rows step DOWN to `bg-main` (the L0 canvas) rather than up; broker tiles use the `.trading-surface` class (12px radius, elev-1, 20px pad, hover elev-2); buttons resolve to `.glass-control` (surface-2 + hairline), `.glass-control-accent` (solid #406AE4, white ink, elev-1) and `.glass-control-danger` (12% red tint over wrap). Pill/rounded-full is used heavily for secondary and destructive controls in Settings, while foundation Buttons are 8px-radius — that inconsistency is as-built.

TYPE ROLES AS ACTUALLY RENDERED: the foundation PageHeader H1 is `text-display-sm` = 40px / line-height 1.1 / -0.02em at font-weight 400 (used on /inbox, /alerts, /settings). /referrals bypasses PageHeader entirely and hand-rolls a 22px semibold H1. Section H2s inside Settings tabs are `font-display text-xl` (20px semibold). EyebrowMono is misleadingly named: it renders Geist SANS, 12px, uppercase, tracking 0.12em, semibold, muted — not mono. PageHeader's own `eyebrow` prop IS mono (11px, tracking 0.1em). All numerics use the MONO token = var(--font-mono) + tabular-nums.

MOTION — only /referrals animates: framer-motion Reveal (opacity 0→1, y 10→0, 0.45s, cubic-bezier(.16,1,.3,1)) on the header (0s), hero (0.05s), stats (0.1s), credit banner (0.15s), list (0.2s), and each of the first nine rows staggered at 0.04s. StatTile numerals count up over 0.6s on first in-view. Everything else is colour/transform-only micro-motion.

TOAST vs INLINE BANNER — /inbox and /alerts report through sonner toasts. /settings deliberately does NOT: it has ONE global message banner at the top of the panel column (green up-tinted with a CheckCircle, or red down-tinted with an AlertCircle) that every save handler, broker connect/disconnect, kill switch and data action writes into; ModePanel's theme/experience toast is the only sonner call on the page. /referrals uses neither — errors render as an inline red `rounded-xs border-down/40 bg-down/10` strip.

KNOWN AS-BUILT ROUTING QUIRK — the Settings section rail's 'WhatsApp digest' and 'Security + 2FA' items router.push to /settings/whatsapp and /settings/security. Neither directory exists; middleware.ts rewrites them to /settings?tab=channels and /settings?tab=security, and neither 'channels' nor 'security' is a valid TabKey, so both silently land the user back on the Profile tab. Document it, do not design around it as if those panels existed.

DESTRUCTIVE-ACTION PATTERN — every irreversible control uses foundation ConfirmDialog (Cancel takes initial focus so Enter always backs out; confirm button shows 'Working…'), with one exception: /referrals still guards 'Rotate code' with a native window.confirm(). Settings holds two ConfirmDialogs — 'Activate kill switch?' (page-level, fired from the Risk-profile tab) and 'Flatten the book and halt trading?' (inside KillSwitchPanel) — and KillSwitchPanel's result card deliberately persists on screen rather than living in a toast, because a partial liquidation must show which symbols are still open.

P&L / SEMANTIC COLOUR DISCIPLINE — green and red appear ONLY as state semantics (Connected/Rewarded/Armed vs Expired/Error/ACTIVE-halted/Delete), never as chrome. Amber (#F0A94F dark / #9A4D00 light, the `highlight` token) carries referral credit, the quiz-recommendation banner, partial kill-switch failure and 'Expired' broker status. The two brand exceptions on the whole surface group are WhatsApp #25D366 and Telegram #229ED9 on the /referrals share buttons, plus the seven broker monogram fallback fills in BrokerConnectTile.

## `/inbox` — Inbox (notifications feed)

**File** `app/(platform)/inbox/page.tsx` · **286 LOC** · **Access** authed. No tier gate. Renders inside the (platform) group, which redirects to /onboarding/broker-connect when onboarding is incomplete. Unauthenticated users never reach it (middleware gating).

**Shell** — (platform) AppShell — fixed 240px left sidebar (68px collapsed), fixed 72px right icon rail, ComplianceFooter, plus SystemHaltBanner + AutopilotStickyStop from app/(platform)/layout.tsx. Page content is additionally capped at max-w-4xl (896px) and centred inside AppShell's max-w-[1440px] px-4 md:px-6 gutter.

**Purpose.** The single notifications feed: every signal publish, position event, risk/system alert and AI summary the backend has pushed to this user, newest-first, tabbed into four buckets. The user comes here to triage what happened while they were away, mark it read, and click through to the signal or portfolio row that caused it. It concludes 'here is everything outstanding, and here is the one place to act on it'.

**States & data.** Single fetch on mount: api.notifications.getAll({ limit: 50 }) → { notifications: Notification[] } where Notification = { id, user_id, type, title, message, data?, is_read, created_at }. No polling, no SWR — plain useState/useEffect; the RefreshCw button re-runs the same call. Loading = 3 NotifSkeletons. Fetch failure = sonner toast.error('Could not load notifications', { description: err.message }); the list stays empty and the zero-state renders. Mark-read is optimistic (local is_read flip first, POST after, failures swallowed silently). Mark-all-read is optimistic across the whole array, then toast.success(`Marked ${n} as read`); on failure toast.error('Could not mark all as read') and a full refetch. Unread count is derived, not fetched.

**Interactions.** Four-tab client filter (no refetch). Refresh icon button (spins, disabled while in-flight). 'Mark all read' appears/disappears with the unread count. Whole-card click either navigates via Link (and marks read en route) or, when no route can be inferred, acts as a mark-read button. ⌘K/Ctrl+K command palette and ESC come from AppShell. No modals, no sheets, no sorting, no bulk selection.

**Responsive.** Page is a single 896px column at every breakpoint — it never becomes multi-column. PageHeader stacks title above actions below md and becomes a row with items-end at md. Body padding steps 16px → 24px at md. The tab pill rail is inline-flex and can overflow horizontally on very narrow screens. AppShell drops both fixed rails below lg and swaps in the mobile Topbar + MobileDrawer; the 240px/72px margins are lg-only.

## `/alerts` — Alerts Studio (event × channel routing)

**File** `app/alerts/page.tsx` · **387 LOC** · **Access** authed + Pro tier gate. Three distinct pre-states: (1) authLoading or tier loading → spinner; (2) no user → sign-in EmptyState; (3) authed but tierData.features.alert_studio false and is_admin false → explicit Pro paywall EmptyState (never the grid's raw 403). Admins bypass the gate. Only Pro/Elite/admin mount the studio body, so the preferences fetch never fires for Free users.

**Shell** — Route lives OUTSIDE the (platform) group (app/alerts/page.tsx), so it wraps itself: every return path renders <AppShell>{…}</AppShell> directly. Same 240px sidebar / 72px right rail / 1440px cap / ComplianceFooter, but no SystemHaltBanner or AutopilotStickyStop. Page body is w-full (no extra max-width).

**Purpose.** The Pro control room for alert delivery: which of the 18 backend event types goes to which of the 4 channels, whether each channel is actually connected, and a per-channel test send to prove delivery. The user comes here to stop being spammed, or to guarantee they get woken up for the events that matter (unprotected F&O position, portfolio drawdown). It concludes 'this exact event will reach me on this exact channel, and I have proven it works.'

**Components** — `components/foundation/PageHeader.tsx` · `components/foundation/Button.tsx (primary | secondary | ghost | ai; sizes sm/md)` · `components/foundation/Badge.tsx` · `components/foundation/StatTile.tsx` · `components/foundation/EmptyState.tsx` · `components/foundation/Toast.tsx (sonner)` · `components/settings/AlertPreferencesGrid.tsx` · `components/shell/AppShell.tsx` · `components/shell/ComplianceFooter.tsx` · `contexts/AuthContext.tsx (useAuth)`

**States & data.** Two SWR keys, both revalidateOnFocus:false. 'user_tier' → api.user.getTier() gives { tier, is_admin, features, copilot_daily_cap }; hasStudio = features.alert_studio || is_admin. 'alerts_preferences' → api.alerts.preferences() returns { preferences: Record<event, Record<channel, boolean>>, events: [{key,label,description}], channels: [{channel, connected, detail}] } — the studio body and AlertPreferencesGrid share this one key so SWR dedupes to a single GET even though both mount it. Writes: api.alerts.toggle(event, channel, enabled) PATCHes one cell and the response is pushed straight into cache (mutate(res,false)); api.alerts.bulkUpdate(matrix) writes all 18×4 and globalMutate('alerts_preferences', res, false) re-renders both panels; api.alerts.test(channel) POSTs and returns { delivered, channel, detail } — delivered true → toast.success('Test sent to Telegram', { description: detail || 'Check the channel for the test alert.' }), false → toast.error('{Channel} not delivered', { description: detail || 'Connect the channel in Settings, then retry.' }). Channel-panel loading/error render as plain sentences, not skeletons.

**Interactions.** Per-channel 'Send test' with in-button spinner + result toast.
